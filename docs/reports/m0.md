# M0 報告（調査と検証）— 2026-10-15

ブリーフ §12 の形式。終了条件「上流との一致（SNR 60dB 以上）」「WebGPU／WASM それぞれの 1 チャンクの処理時間」のうち、**一致は達成**（fp32 ONNX で 115〜137 dB）、**WASM は計測済み**、**WebGPU は本環境に GPU がないため未計測**（利用者の実機で計測する計測ページを M1 で用意する）。

## 実施したこと

- 上流 MERL 実装（`mrx.py` / `separate.py` / `dnr_dataset.py`）と audiojs のモデルカードから、STFT 仕様・音源の並び・前処理を確認。MERL のチェックポイントから ONNX（fp32 / fp16 / int8）を自前で書き出した（`scripts/export/build_onnx.py`）。
- 同じ信号を上流 PyTorch・NumPy 移植・ONNX（onnxruntime）に通して音源ごとの SNR を計測（`scripts/parity/parity.py`）。TypeScript の STFT / iSTFT を実装し、NumPy の試験ベクトルと一致を確認（`src/audio/stft.ts`）。
- onnxruntime-web の WASM（単一スレッド、Node）で 10〜20 秒チャンクの処理時間とメモリを計測（`scripts/bench/ort-web-node.mjs`）。

## 計測結果

### 上流との一致（10 秒ステレオの合成信号、上流 PyTorch を基準、音源ごとの SNR）

| 実装 | サイズ | music | speech | sfx | 備考 |
|---|---|---|---|---|---|
| NumPy 移植 | — | 136.1 dB | 112.1 dB | 128.4 dB | |
| ONNX fp32 | 122.0 MB | 136.9 dB | 114.6 dB | 128.9 dB | **目標 60 dB を達成** |
| ONNX fp16（重みのみ） | 61.1 MB | 86.8 dB | 53.7 dB | 72.9 dB | |
| ONNX int8（閾値 40 dB、11 本を fp16 に） | 42.4 MB | 57.2 dB | 25.4 dB | 43.5 dB | |
| ONNX int8（閾値 38 dB） | 35.9 dB | 55.2 dB | 31.4 dB | 41.2 dB | |
| ONNX int8（全 39 本 int8） | 30.9 MB | 54.0 dB | 25.8 dB | 41.7 dB | audiojs と同じ方式（対称・出力チャンネルごとのスケール） |

- speech の値が低いのは、この合成信号の speech 成分が混合より約 40 dB 小さく、基準そのものが小さいため。**混合の電力を基準にした誤差**は int8（全 int8）でも music 54.6 dB、speech 90.9 dB、sfx 55.8 dB 下にある。
- int8 の確定は、実音声（セリフ＋BGM）の試験素材で聴いてから行う（下記「決める必要があること」）。
- TypeScript の STFT は NumPy と 145〜151 dB で一致、STFT→iSTFT 往復は 163〜177 dB。

### 処理時間（WASM、単一スレッド、Node 22、Intel Xeon 2.1 GHz の vCPU）

| モデル | 条件 | 推論時間 | 音声 1 秒・1ch あたり | RSS |
|---|---|---|---|---|
| fp32 | 20 秒 × 2ch（T=3446） | 22.2 s | 0.56 s | 2.6 GB |
| int8 | 20 秒 × 2ch | 22.2 s | 0.56 s | 2.7 GB |
| int8 | 20 秒 × 1ch | 11.0 s | 0.55 s | 1.4 GB |
| int8 | 10 秒 × 2ch | 10.6 s | 0.53 s | 1.4 GB |
| int8 | 10 秒 × 1ch | 5.3 s | 0.53 s | 1.0 GB |

- int8 は読み込み時に fp32 へ戻すため速度は同じ（想定どおり）。ステレオで **実時間の約 1.1 倍**（10 分の動画で約 11 分）。デスクトップの CPU ならこの 2 倍前後の速さが見込めるが、要実測。
- メモリは B=1（チャンネルごと）・10〜20 秒チャンクで 1.0〜1.4 GB（Node の RSS）。ブラウザの WASM は 4 GB 上限なので、**チャンネルごとに処理し、チャンクは 10〜20 秒**にする。M1 でブラウザ内の実測値を取る。
- TypeScript の STFT＋iSTFT（3 音源分）：音声 1 秒・1ch あたり約 0.27 秒（8192 点が大半）。M1 で FFT を最適化する余地あり。
- **WebGPU：未計測**（本コンテナのヘッドレス Chromium 141 に WebGPU アダプタなし）。

### 到達できなかったホスト

huggingface.co は許可されたが、ファイル本体の配信元 `us.aws.cdn.hf.co` / `cdn-lfs.hf.co` は遮断されていて `mrx.int8.onnx`（31,287,081 bytes、SHA-256 `d876c92d…8424`）は取得できなかった（モデルカードは取得済み）。`download-r2.pytorch.org` も遮断のため CPU 版 torch は取れず、PyPI の CUDA 同梱版（約 3 GB）を導入した。archive.org / Wikimedia Commons / freesound / OpenSLR も遮断で、公開素材の取得はできない。

## 決める必要があること

1. **試験素材**（§11）：公開素材サイトに到達できないため、次のいずれかをお願いしたい。(a) ファイルをアップロードする：ご自身の声（30〜60 秒）、CC0 の楽曲（歌あり・歌なし）、CC0 の効果音（足音・ドア・車・チャイム）。出典は `tests/fixtures/SOURCES.md` に記録する。(b) 環境の Allowed domains に `archive.org`（パブリックドメインの朗読）と `upload.wikimedia.org` を足す。推奨は (a)。
2. **配布モデル**：全 int8（30.9 MB）を既定にし、試験素材で聴いて問題があれば fp16 に切り替える。
3. 任意：`us.aws.cdn.hf.co` と `cdn-lfs.hf.co` を許可すると audiojs 版との突き合わせができる（必須ではない）。
