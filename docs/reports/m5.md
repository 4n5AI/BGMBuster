# M5 報告：仕上げと公開

## 実施したこと

- 公開物：README（日・英）、`LICENSE`（MIT © 2026 4n5-Studio）、`THIRD_PARTY_NOTICES.md`（MRX / onnxruntime-web / Mediabunny / aac-encoder + FFmpeg の全文）、`VERSION`、`public/.nojekyll`、OG 画像と favicon、`index.html` のメタ情報。
- 公開手順：`.github/workflows/deploy.yml`（main への push と手動実行で npm ci → typecheck → test → build → Pages へ配備。`configure-pages` の `enablement: true` で Pages を自動有効化）。https://4n5ai.github.io/BGMBuster/ で稼働中（run #1〜#3 すべて成功、現在 main は `32426aa`）。
- ユーザーの実機テスト（Kling 生成の MP4、H.264 720p 24 fps、AAC-LC 44.1 kHz ステレオ、17 秒）を受けて次を追加・修正した。
  - 「効果音の音量」スライダー（`86733e2`）：MRX が低い持続音（ドローン）や環境音を「効果音」に分類するため、BGM 0 でも残る音を下げられるようにした。
  - 推論バックエンドの自己診断（`32426aa`）：1 秒の固定プローブをモデルに通し、マスクの平均値を WebAssembly の参照値と比較する。WebGPU で 5% 以上ずれれば WebAssembly に切り替える。`?backend=wasm|webgpu` で強制もできる。
  - エンコーダー遅延の実測が動いていなかったバグの修正（`aa43412`、ブランチのみ・未公開）：`measureEncoderDelay` の引数順が逆で常に既定値 1024 に落ちていた。ユーザー環境（ネイティブ AAC エンコーダー、遅延 2112）では音声が 1088 サンプル（24.7 ms）遅れていた。引数をオブジェクト化し、プローブをチャープに変更、相関が弱いときは既定値に戻す。計測値を「技術情報」の「書き出し」行に表示する。
- ユーザーから受け取った処理後 MP4 を、元動画と上流（PyTorch 版 MRX）の期待出力と比較した（下記）。

## 確認できた事実と未確認

確認できた事実

- ユーザー環境で作られた処理後ファイルは、上流モデルの出力と一致している（1 秒ごとの RMS が全区間で 1 dB 以内、全体の SNR 25.4 dB。期待出力そのものを AAC 128 kbps に通したときの SNR が 27.3 dB なので、差はほぼ AAC の符号化雑音）。int8 の重みとチャンク処理は実素材でも上流と同等に動いている。
- 映像パケットは元と同一（ffmpeg の MD5 一致、409 フレーム、先頭フレームの表示時刻 0）。元ファイルの映像トラックにあった一定の合成オフセット（ctts 2048/12288 s と、それを打ち消す `elst`）は Mediabunny が pts に畳み込み、出力では pts = dts になっている。
- 「BGM が残る」の実体はモデルの分類：17 秒のうち音楽と判定されたのは 2–4 秒と 11–14 秒だけで、そこは 27〜30 dB 下がっている。5–10 秒は効果音（低い持続音）、0–2 秒と 15 秒は「セリフ」（短い打撃音と、声のような上昇音）に分類され、そのまま残る。
- 処理後ファイルの音声は元より 1088 サンプル遅れていた（`elst media_time` = 3072 = 元の先頭オフセット 2048 + 既定値 1024）。原因は上記の引数順バグ。
- 修正後、手元の Chromium で Opus/WebM の実測は遅延 0・相関 1.000、MP4（Opus 入力）/MOV/WebM の往復は同期 0.00 ms・映像同一、アプリの e2e 12 手順はすべて PASS。

未確認

- ユーザー環境の処理方式（WebGPU か WebAssembly か）、GPU 名、自己診断の結果。「技術情報」の表示を待っている。
- ネイティブ AAC エンコーダー／デコーダーでのチャープ実測値（手元の Chromium は AAC をデコードできない）。2112 と出るはずだが未確認。
- 0–2 秒と 15 秒の「セリフ」判定が正しいか（声なのか、声に似た効果音なのか）。ステムを聴き比べる必要がある。
- WebGPU の処理時間と、Safari / Firefox / スマートフォンでの動作。
- 再ミックス方式 A/B の聴き比べ（人手）。
